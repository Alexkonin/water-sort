# Разлей по цветам — MVP

Головоломка в жанре water sort. Чистый HTML/JS, без сборки, без сервера, без зависимостей.
Уровни генерируются на устройстве и проверяются солвером — все гарантированно решаемы.

## Файлы

| Файл | Что делает |
|---|---|
| `index.html` | вся игра: логика, генератор уровней, солвер, анимации, интерфейс |
| `manifest.json` | описание PWA (имя, иконки, цвета) |
| `sw.js` | офлайн-кэш |
| `icon-192/512/180.png` | иконки для экрана «Домой» |

## Посмотреть у себя

Достаточно открыть `index.html` двойным кликом. Офлайн-режим и установка на телефон
при этом не работают (нужен http/https) — но играть можно.

Локальный сервер, если нужен полноценный режим:

```bash
python3 -m http.server 8123 --directory "Мои приложения/water-sort"
```

## Как отправить жене

Самый простой путь — выложить папку на бесплатный статик-хостинг и отправить ссылку.

1. Открыть <https://app.netlify.com/drop>
2. Перетащить туда папку `water-sort` целиком
3. Скопировать выданную ссылку и отправить

Ссылка открывается в любом браузере, ничего устанавливать не нужно.
Чтобы ссылка осталась навсегда — бесплатный аккаунт Netlify (кнопка «Claim»).
Альтернативы с тем же результатом: Cloudflare Pages, GitHub Pages, Vercel, Yandex Object Storage.

Можно отправить и сам файл `index.html` в мессенджере — он самодостаточный, — но на iPhone
файлы `.html` открываются непредсказуемо. Ссылка надёжнее.

## Поставить как приложение на телефон

Работает только по ссылке (https), не с файла.

- **iPhone:** открыть ссылку в Safari → «Поделиться» → «На экран „Домой“»
- **Android:** меню Chrome → «Установить приложение»

После установки игра открывается на весь экран, без адресной строки, и работает офлайн.
Прогресс хранится в браузере устройства (localStorage).

## Обновление

После правок в `index.html` поменяйте номер версии в `sw.js` (`const CACHE = 'watersort-v2'`),
иначе у тех, кто уже открывал игру, останется старая версия из кэша.

## Как устроена игра

- Состояние — массив стеков: `state.tubes = [[0,1,1,2], [2,0,...], [], []]`, числа = индексы цветов.
- `canPour` / `pourCount` / `applyMove` — правила: переливать можно только на такой же цвет
  или в пустую пробирку, и не больше, чем влезет.
- `generateLevel(n)` — раскладка по сиду от номера уровня: у всех игроков уровень N одинаковый.
  Раскладка перемешивается случайно, затем `solvable()` (поиск в глубину с отсечением
  повторов по канонизированному состоянию) проверяет решаемость. Нерешаемые отбрасываются.
- В пробирке 5 слоёв (`CAP`, дублируется в CSS как `--cap`).
- Сложность растёт числом цветов: 3 → 12 к 55-му уровню (до 14 пробирок, 3 ряда).
  Пустых пробирок всегда две.
- **Разная вместимость.** `state.caps[i]` — сколько слоёв вмещает пробирка. С 15-го
  уровня появляются маленькие скляночки на 2 слоя (`SMALL_CAP`), с 30-го — две.
  Они стартуют пустыми и работают как временная полка.
  Важная тонкость: «собранной» (из неё нельзя выливать) считается только
  полноразмерная пробирка — `isSolved` требует `cap === CAP`. Иначе цвет, налитый
  в маленькую доверху, запирался бы в ней и уровень становился нерешаемым.
  При этом победа требует, чтобы каждый цвет лежал целиком в одной полноразмерной
  пробирке, — значит маленькие к финалу всё равно приходится освобождать.
- Порядок пробирок перемешивается (`shuffleTubes`), иначе пустые и маленькие
  выстраиваются хвостом в конце поля. На решаемость перестановка не влияет.
- Пробирки в ряду идут группами по три (элемент `.spacer`) — так поле читается,
  когда их много.
- **Скрытые слои.** С 10-го уровня нижние слои закрыты знаком «?»: `state.hidden[i]` —
  сколько нижних слоёв закрыто. Слой раскрывается, когда становится верхним
  (`revealTops`), а собранная пробирка открывается целиком — иначе не видно, что она
  готова. Глубина: 1 слой на уровнях 10–19, 2 слоя с 20-го. Верхний слой виден всегда,
  поэтому игрок всегда знает, что переливает.
  Уровень остаётся решаемым (солвер видит все цвета) — незнание компенсируется отменой
  хода и запасной пробиркой, как принято в жанре. Отмена возвращает и скрытие тоже,
  иначе через откат можно было бы «подсматривать» цвета.
- Генерация 60 уровней занимает ~60 мс, худший уровень ~4 мс — задержки не видно.

## Параллельные переливы

Ход применяется к модели СРАЗУ (`doMove`), а анимация — только показ. Поэтому можно
затевать следующий перелив, не дожидаясь предыдущего: занятыми считаются лишь две
задействованные пробирки (`state.busyTubes`), остальное поле кликабельно.

Что из этого следует по коду:
- `animatePour` не трогает состояние — состояние источника до хода приходит в `plan`
  (`srcColors`, `startA`, `startB`), иначе параллельные переливы читали бы чужие данные.
- SVG-оверлеи взяты в пул (`acquireSVG`/`releaseSVG`), у каждого свой `clipPath`-id —
  один общий слой два перелива поделить не могут.
- `state.anim` — счётчик переливов в полёте. Кнопки (отмена, +пробирка, пропуск) и
  перестроение поля при resize ждут, пока он обнулится; экран победы показывается,
  когда осядут все переливы.

## Анимация перелива

Главная задача — чтобы жидкость реально выливалась, а поверхность оставалась
горизонтальной, а не крутилась вместе со стеклом. Решение — как в игровых движках
(Unity/Godot): поверхность считается в МИРОВЫХ координатах, а форма пробирки лишь
обрезает её.

Как это устроено (функция `animatePour`):
- Вся анимация (подъём → наклон → слив → возврат) идёт единым циклом `requestAnimationFrame`,
  и SVG-жидкость рисуется В КАЖДОМ кадре синхронно с трансформом стекла. Это убирает
  «хлопок» пустой колбы, рассинхрон границ и рывок на входе (раньше подъём был на
  CSS-переходе, а SVG подхватывался только после наклона).
- Пробирка-источник наклоняется **горлышком вниз** (~116–132°) — жидкость скапливается
  у носика и льётся через него; воздушный карман образуется у закрытого дна (вверху).
- Наклонённая колба не вылезает за верх экрана: если её верхняя точка выше поля, вся
  сцена опускается (`TOP`-кламп).
- Струя — широкая лента из самого горлышка (`streamW`), без «кружка» у носика, чтобы
  читалось как слив из колбы, а не капля.
- На время перелива DOM-жидкость источника прячется, а взамен в **SVG-оверлее** (`#pourfx`,
  создаётся один раз) рисуются: полость пробирки как `clipPath` (наклоняется вместе со
  стеклом) и слои жидкости — **горизонтальные полосы** в мировых координатах. Пересечение
  даёт честно горизонтальную поверхность при любом наклоне. SVG — вектор, поэтому чётко
  на ретине и при θ=0 совпадает с DOM пиксель-в-пиксель.
- Уровень слоёв ищется по объёму: `areaBelow` (отсечение полигона полуплоскостью +
  формула шнуровки) и `surfaceForArea` (бинарный поиск уровня). Цвета идут в ОБРАТНОМ
  порядке хранения — верхний (сливаемый) цвет оказывается у носика.
- Струя — SVG-лента (`ribbonPath`, квадратичная безье с сужением книзу и «губой» у носика),
  привязана к нижнему углу горлышка и к поверхности приёмника. Приёмник остаётся на DOM
  (он вертикальный, корректен и так).

Тайминги — константы наверху блока «анимация переливания»: `T_TILT` (наклон),
`T_FALL` (струя летит до поверхности), `T_UNIT` (на один слой), `T_TAIL`. Угол наклона —
`angStart`/`angEnd`, ограничены `fitMax` (чтобы наклонённая пробирка не вылезла за экран).
Геометрия связана с CSS: `TUBE_WALL`, `cavityPolygon` должны совпадать с `.tube`/`.liquid`.
